    Pick your route

    Connect in the browser

    One script finds bWalletX by BRC-100 discovery. You get the full wallet interface, the same as window.CWI.

    <script src="https://bwalletx.com/connect.js"></script>
const { wallet, identityKey } = await bWalletX.connect();
const { signature } = await wallet.createSignature({ data, protocolID: [1, 'my app'], keyID: '1' });

    Sign in with bWalletX

    The wallet signs a one-time challenge from your server. Your server checks it with @bsv/sdk. The identity key is the user ID.

    <script src="https://bwalletx.com/connect.js"></script>
const r = await bWalletX.signIn({ challenge: (identityKey) => post('/auth/bwalletx/challenge', { identityKey }) });
await post('/auth/bwalletx/verify', { identityKey: r.identityKey, nonce: r.nonce, signature: r.signature });

    Local agent API and MCP

    bwalletx serve runs an agent account as a BRC-100 wallet on localhost:3321, where sites already look for a desktop wallet. bwalletx mcp gives AI agents the same account, inside your limits.

    npm i -g bwalletx
bwalletx serve -a trader --origin localhost:3000   # key-file agent accounts only
claude mcp add bwalletx -- npx -y bwalletx mcp

    Public read APIs

    Open endpoints, no key: look up names and profiles for a wallet, and let agents list and buy Store items with their own wallet.

    curl 'https://pay.bwallet.space/api/paymail/lookup?key=<identityKey>'
curl https://pay.bwallet.space/api/paymail/id/npg@bwalletx.com
curl https://bwalletx.com/api/agent/products

    What works today

    • ✓ LiveTry-it console ✓ on this page: run read-only BRC-100 calls (getPublicKey, listOutputs, listActions and more) and a test createSignature against your own wallet, then copy the code
    • ✓ LiveConnect from Chrome or Brave with the bWalletX extension, or from the browser inside the bWalletX app
    • ✓ LiveEvery BRC-100 call (sign, encrypt, pay, keys), each one approved by the user in their wallet
    • ✓ LiveSign in with bWalletX: connect.js and @bwalletx/connect 0.7.0 on npm. You run the two server routes
    • ✓ LivePhone and web wallet pairing by QR code, on the sign-in guide
    • ✓ Livebwalletx serve on localhost:3321 and bwalletx mcp (CLI 0.5.0 on npm)
    • ✓ LivePublic read APIs: paymail names, profiles and the name log, and the agent Store API
    • Not builtPhone pairing on this page. Use the sign-in guide for now.
    • Not builtWebhooks. Nothing calls your server when something happens in a wallet.
    • Not builtAn account API with API keys. No server-side access to a user's wallet or balance; everything goes through the user's own wallet.
    • Not builtHosted sign-in or an OAuth-style redirect. You verify the signature on your own server.
    • Not builtA test wallet. No testnet build or headless bWalletX; test your server with ProtoWallet from @bsv/sdk.
