Names, handles and paymail

Send to $handle or name@bwalletx.com. The paymail server moved domain twice, and social sign-in became a verified name.

Sending to a name

Bitcoin addresses are hard to read aloud. On 1 October we added sending to a $handle or a paymail address.

Our own paymail server

We wrote a paymail server with no server keys. Names are registered with a signed request, payment destinations are derived from the wallet's public key, and incoming payments wait in an inbox until the wallet collects them.

The domain moved twice. It started on b0ase.com. The same day it moved to bwallet.space. Then we removed b0ase.com entirely, because, as the commit says, it never had DNS set up. On 4 October the address shown in the app became name@bwalletx.com, and bwallet.space stayed as an alias for every name.

Choosing a handle

New wallets get a "Choose your handle" step after create or restore. Claiming a paymail name is free. The same step offers a personal $NAME token and room (post 005), which costs a fee and is shown before you pay.

Continue with X or Google

On 4 October we added "Continue with X / Google" on Create Account. If you sign in, you get a verified name such as name.x. A plain name can be claimed by anyone; a verified name shows that the person behind it controls that X or Google account.

The design changed during the day. First the chat server (bit-sign) handled the sign-in. Then we moved it to bWalletX's own server, and bit-sign keeps nothing: it only confirms the sign-in ticket. Then we decided one wallet has one identity, and a verified social name always wins over a plain one.

Social sign-in is off in the store build, pending Apple's guideline 4.8 on sign-in options.

Update, 30 Oct 2026: Create New Wallet now uses a password and your 12 words. The welcome screen can start linking X or Google, finished once your wallet is set up, and you can link them any time under Settings › Link your accounts. A linked account gives a verified badge; you choose your own handle.

A detail that took longer than expected

Placeholder names such as "Anonymous" or "Account 1" kept showing up in places where a real name should be. We now never show them; the paymail name is used instead.

What's not done

  • Handles are not tradeable yet. The numbered accounts and tradeable handles spec is design only.
  • Name resolution depends on our paymail server being up.
  • Social sign-in is not in the store build.
